¿Qué es y para qué sirve?

El conector Google Docs Workspace permite que el agente de Ruvic lea, cree y edite documentos accesibles por uno o varios usuarios de tu dominio Google Workspace, usando una sola credencial administrada centralizadamente por tu equipo de TI — sin que cada usuario tenga que autorizar su propio acceso por separado. Una vez configurado, puedes pedirle al agente cosas como:

  • "Lee el acta de la última reunión del buzón de facturación y resúmela."
  • "Crea un documento nuevo en la cuenta de soporte con el borrador de esta propuesta."
  • "Llena la plantilla del contrato reemplazando {{CLIENTE}} por ACME S.A."

Operaciones soportadas:

Operación Qué hace
docs.read Lee el título y el texto completo de un documento
docs.create Crea un documento nuevo (con texto inicial opcional)
docs.append Agrega texto al final de un documento
docs.replace Busca y reemplaza texto en todo el documento (ideal para plantillas)
Solo para Google Workspace Este conector usa delegación de dominio, una función exclusiva de Google Workspace. No funciona con cuentas de Google personales (@gmail.com) — para esas usa el conector "Google Docs" (OAuth2).

Prerrequisitos

  • Una organización con Google Workspace (no funciona con cuentas personales @gmail.com).
  • Acceso de superadministrador de Google Workspace — es la única persona que puede autorizar la delegación de dominio (paso único, sección 3).
  • Acceso al Google Cloud Console del mismo dominio, con permisos para crear un proyecto y una cuenta de servicio.
  • Acceso del usuario de prueba a al menos un documento (propio o compartido) para las pruebas iniciales.
¿Ya configuraste Gmail, Sheets o Drive Workspace? Puedes reutilizar la misma cuenta de servicio de esos conectores en lugar de crear una nueva — solo hay que agregar el scope de Docs a la misma entrada de delegación en el Admin Console.

Configuración en el fabricante

Vas a crear una cuenta de servicio en Google Cloud y autorizarla mediante delegación de dominio para que pueda actuar en nombre de cualquier usuario autorizado. Esto se hace una sola vez por dominio — después, agregar un usuario nuevo no requiere repetir estos pasos, solo compartírselo al agente por su correo.

  1. Crea (o selecciona) un proyecto en Google Cloud Console.

    Ve a console.cloud.google.com/projectcreate y crea un proyecto (o reutiliza uno existente del mismo dominio).

  2. Habilita la Google Docs API.

    En el menú APIs y servicios → Biblioteca, busca "Google Docs API" y pulsa Habilitar.

  3. Crea la cuenta de servicio (o reutiliza la de Gmail/Sheets/Drive Workspace).

    En IAM y administración → Cuentas de servicio → Crear cuenta de servicio. Dale un nombre (ej. ruvic-docs-workspace) y termina el asistente sin asignar roles adicionales de proyecto.

  4. Genera y descarga la clave JSON.

    Abre la cuenta de servicio → pestaña Claves → Agregar clave → Crear clave nueva → JSON. Se descargará un archivo .json: guárdalo, lo usarás en el formulario de Ruvic.

    [ Captura: pestaña Claves de la cuenta de servicio con el botón "Agregar clave" — reemplazar por assets/img/docs-workspace-sa-key.png ]
  5. Anota el ID de cliente único de la cuenta de servicio.

    En la pestaña Detalles de la cuenta de servicio, copia el ID de cliente único (una cadena numérica larga). Lo necesitarás en el siguiente paso.

  6. El superadministrador autoriza la delegación de dominio (paso crítico).

    Este paso solo lo puede hacer el superadministrador de tu organización de Google Workspace. Ve a admin.google.com → Seguridad → Control de acceso a las API → Delegación en todo el dominio. Si el Client ID ya está agregado (ej. por Gmail, Sheets o Drive Workspace), edítalo y agrega el scope de Docs; si no, pulsa Agregar nuevo e ingresa:

    • ID de cliente: el ID de cliente único copiado en el paso anterior.
    • Alcances OAuth: 
      https://www.googleapis.com/auth/documents

    Guarda. Sin este paso, cualquier intento de conexión falla con el error unauthorized_client.

    [ Captura: pantalla de delegación en todo el dominio con el ID de cliente y los scopes — reemplazar por assets/img/docs-workspace-domain-delegation.png ]
  7. Define qué usuario usarás para la prueba inicial.

    Anota el correo de un usuario del dominio (ej. facturacion@tuempresa.com) para el formulario de Ruvic. Después de configurado, el agente podrá usar cualquier otro usuario autorizado del mismo dominio, no solo este.

Permisos requeridos

Principio de mínimo privilegio: la cuenta de servicio solo necesita este scope de Docs. No autorices scopes de Drive completo ni de otras APIs de Workspace.

Scope Para qué lo usa el conector
documents Leer (docs.read), crear (docs.create) y editar (docs.append, docs.replace) documentos accesibles por el usuario impersonado
La delegación aplica a TODO el dominio A diferencia de OAuth2 por usuario, este scope no se limita a un usuario — la cuenta de servicio puede impersonar a cualquier usuario del dominio con ese permiso, incluidos los que se creen en el futuro. No hay forma de restringirlo a una lista específica de usuarios desde el Admin Console. El conector no solicita el scope completo de Drive: no puede mover, eliminar ni cambiar permisos de archivos.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Google Docs (Google Workspace — cuenta de servicio) y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
JSON de la cuenta de servicio Abre el archivo .json descargado en el paso 4 y pega todo su contenido
Usuario de prueba El correo definido en el paso 7 (ej. facturacion@tuempresa.com)
Timeout de solicitud Opcional; 30 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a Docs API impersonando al usuario de prueba y confirmará que la delegación de dominio funciona.

[ Captura: formulario del conector Google Docs Workspace en Settings → Conectores — reemplazar por assets/img/docs-workspace-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa como facturacion@tuempresa.com (delegación de dominio)". La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba, incluido un segundo usuario.

    Abre una conversación nueva con el agente y pídele:

    "Crea un documento de prueba en la cuenta facturacion@tuempresa.com que se llame 'Prueba Ruvic'."

    Luego prueba con otro usuario del dominio distinto al de la prueba inicial — si el agente responde con resultados reales de ambos sin pedir nueva configuración, la delegación de dominio quedó operativa de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"unauthorized_client" al probar la conexión El error más común. El conector te dirá exactamente qué revisar: 1) que el Client ID esté agregado en el Admin Console (paso 6 de la sección anterior), 2) que los scopes incluyan exactamente https://www.googleapis.com/auth/documents, 3) que el usuario de prueba pertenezca al mismo dominio Workspace. Solo el superadministrador puede corregir el punto 1.
"La Google Docs API no está habilitada en el proyecto de Google Cloud…" Falta habilitar la Google Docs API en el proyecto (paso 2 de la sección anterior). El mensaje del conector incluye el enlace directo de activación; habilítala y espera 1-2 minutos.
"…no contiene un JSON válido" Se pegó un fragmento del archivo o se modificó el contenido. Vuelve a abrir el .json descargado y pega todo su contenido, sin editarlo.
"El documento solicitado no existe, o el usuario impersonado no tiene acceso" El documento no fue compartido con el usuario impersonado, o el document_id tiene un error de tipeo.
"Docs API no respondió correctamente (HTTP 429)" Límite de cuota temporal de la API. Es transitorio; el agente puede reintentar en unos segundos.
El conector aparece "Sin configurar" tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa el JSON de la cuenta de servicio y el usuario de prueba.

Preguntas frecuentes y notas de seguridad

¿El agente puede leer o modificar cualquier documento del dominio?

Solo los documentos a los que el usuario impersonado tenga acceso (propios o compartidos con él) — no todos los del dominio. Como la delegación cubre todo el dominio, la cuenta de servicio puede impersonar a cualquier usuario autorizado, así que en la práctica el alcance depende de qué usuarios uses en el código.

¿El agente puede eliminar documentos o cambiar permisos?

No. El conector solo lee, crea y edita el contenido de documentos (docs.read, docs.create, docs.append, docs.replace). No elimina archivos, no cambia permisos de acceso ni toca otros archivos de Drive.

¿Puedo usar la misma cuenta de servicio que Gmail, Sheets o Drive Workspace?

Sí. Una cuenta de servicio puede tener varios scopes autorizados a la vez en la misma entrada de delegación del Admin Console. Solo agrega https://www.googleapis.com/auth/documents a la lista de scopes existente, separado por coma, sin espacios extra.

Rotación de credenciales

Recomendado cada 90 días o según tu política: genera una nueva clave JSON en Google Cloud Console, actualízala en el formulario del conector, prueba la conexión, y luego elimina la clave anterior. La delegación de dominio no cambia — sigue asociada al mismo Client ID.

¿Qué hago si el JSON se compromete?

  1. El superadministrador elimina o edita la entrada de delegación en el Admin Console (Seguridad → Delegación en todo el dominio) — esto revoca el acceso de inmediato.
  2. Elimina la clave comprometida en Google Cloud Console (IAM y administración → Cuentas de servicio → Claves).
  3. Genera una nueva clave, vuelve a autorizar la delegación con el mismo Client ID, y actualiza el formulario del conector.
Buenas prácticas Usa una cuenta de servicio dedicada (o compartida solo con Gmail/Sheets/Drive Workspace); autoriza únicamente el scope mínimo; nunca compartas el JSON por canales no seguros; y revisa periódicamente en el Admin Console qué Client IDs tienen delegación de dominio activa en tu organización y con qué scopes.
